记号：K=条件数(=anchor 数)，P=患者数，V/E=H 的节点/边数。关键洞察：从"一个 anchor 多跳到所有患者"做一次 BFS，即可同时拿到该 anchor 到每个患者的最短路径——不必逐个患者召回。这是 shared 把 P 从复杂度里消掉的根因（_traversal.py:3-6）。

D数据流与数据结构

核心中间结构

  • H：query-conditioned graph，G 副本、删数值失败边（MultiDiGraph）
  • paths / all_paths：dict[(cid, pid)] → [anchor,…,pid] 或 None
  • acc[cid]：{matched, distance, path, cost, reason, pruned?}（每患者每条件一条）
  • edge_costs：dict[(u,v)] → edge_cost（去重缓存）
  • sub_nodes / sub_edges：患者并子图，边按 (u,v,key) 去重
  • RetrievalResult：最终每患者一条（见 Step 7）

edge_cost（hub 惩罚）

c(e) = base(1.0) + ρ · log(1 + deg(v))
  • ρ=0：每边代价 1（纯跳数）
  • ρ=1.3：进入高数 hub 的边变贵 → 路径代价↑ → PCST 更易剪、Steiner 打分更低
  • 作用于"目标节点 v"的度数，惩罚 hub 中转

连通子图构造示例（Step 4）

条件 C1(anchor=A1)、C2(anchor=A2)，患者 P004，都命中： C1 path: A1 → X → P004 C2 path: A2 → Y → P004 （也经 X？下面演示共享边） 若 C2 path 改为 A2 → X → P004（与 C1 共享边 X→P004）： sub_nodes = {P004, A1, A2, X} sub_edges = {A1→X, X→P004, A2→X} ← X→P004 只计 一次 union_cost = c(A1→X) + c(X→P004) + c(A2→X) 连通性：A1→X→P004 且 A2→X→P004，均汇到 P004 ⇒ 天然连通

E差异速查（三处分歧点）

① Step 2 · 找路径

  • BFS：一锚一次 BFS→全患者（O(K·(V+E))）
  • Steiner：每(锚,患者) BFS（O(K·P·(V+E))）
  • PCST：同 Steiner
  • shared：改回一锚一次 BFS→全患者（O(K·(V+E))）

② Step 3 · 剪枝  ③ Step 6 · 打分

  • BFS：不剪 · score_generic
  • Steiner：不剪 · score_steiner
  • PCST：路径代价>prize 则剪 · score_generic
  • shared：剪枝/打分与各自朴素版一致
一句话总结："召回连通子图"是 5 种实现共用的并路径机制（Step 4，以患者为端点天然连通）；算法差异只在遍历策略（Step 2：一锚全患者 vs 逐患者）与取舍策略（Step 3：剪/不剪）。shared 变体不改变语义，只把 Step 2 的 P 因子从复杂度中消除。

F检索机制澄清（不是"只取交集"）

每个条件 → 一堆 anchor→患者 路径

  • 在硬过滤图 H 上扩散（数值型 anchor 的不满足边已删）
  • categorical：anchor 可达患者 = 满足
  • numeric：anchor→患者边值须满足 op value（如 LDH>300）
  • 每条件得到一个"满足患者集"+ 到每个患者的最短路径

结果 ≠ 只取交集

  • 对每个患者产一条 RetrievalResult，coverage_count=命中条件数（0..m）
  • strict cohort (m/m) = 各条件患者集的交集（仅 BFS/Steiner）
  • PCST 先按路径代价>prize 剪条件，再做交集 → cohort 可能更小
  • 每患者子图 = 命中路径并集（非交集；各路径终到患者→天然连通），共享边去重
修正直觉："一堆轨迹连到患者、取交集得结果" = BFS/Steiner 的 strict cohort 准确直觉；但管线还做 per-patient coverage + 并子图 + 打分排名，PCST 多了代价剪枝，不只是交集。

HSQL 下沉方案（hub→patient 边离图进 SQLite，hub 节点 BFS+SQL 并行）

下沉规则

  • 节点 patient-边数 > 20
  • 边指向 patient
  • 边类 ∈ {number, text}（数值 + 确诊/事件/性别等标签）
  • 满足则 hub→patient 边进 SQL；hub→非patient 边保留在图里

hub 节点检索：BFS + SQL 并行

  • (1) SQL 查询：该 hub 的 patient 扇出
    若 hub==numeric anchor → WHERE value op ?；否则无过滤
  • (2) BFS 续展：沿 hub 保留的非 patient出边多跳找患者
  • 两路命中合并进 hits（reason=SQL / BFS）
CREATE TABLE hub_patient_edges ( hub TEXT, patient TEXT, kind TEXT, -- number|text value REAL, unit TEXT, raw_relation TEXT, relation_type TEXT, chunk_id TEXT, valid_at TEXT, invalid_at TEXT); CREATE INDEX idx_hub ON hub_patient_edges(hub); CREATE INDEX idx_hub_val ON hub_patient_edges(hub, value); -- 数值范围扫描

流程图

NetworkX 图（瘦身后）

  • 非 hub 节点 + 全部边
  • hub 节点保留
  • hub→非patient 边保留
  • hub→patient 边已移除

SQLite 表 hub_patient_edges

  • hub→patient 边（高扇出）
  • 索引 idx_hub / idx_hub_val
  • 数值条件 → 范围扫描
  • 确诊/标签 → 存在性查询

检索遇 hub 节点

  • (1) SQL 查 patient 扇出
  • (2) BFS 续展非patient边
  • → 合并 hits
